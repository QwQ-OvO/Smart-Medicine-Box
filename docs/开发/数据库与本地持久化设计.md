# 数据库与本地持久化设计

版本：0.2 自评修订稿 · 2026-10-10 · 状态：未实施；修改记录见[设计自评与迭代记录](设计自评与迭代记录.md)。

首版使用一个 IndexedDB 数据库，由 Dexie 管理 schema。数据库位于用户浏览器，后端不复制这些数据。图片 Blob 与文本同库，确保一次保存可以整体提交或回滚。

## 1 数据模型

| Store | 字段 | 索引与约束 |
| --- | --- | --- |
| packages | id、medicineName、nameKey、label、labelKey、revision、createdAt | 主键 id；nameKey；唯一复合 [nameKey+labelKey] |
| observations | id、packageId、seq、locationText、confirmedAt、source、photoId? | 主键 id；唯一 [packageId+seq]；packageId |
| feedback | id、packageId、observationId、seq、outcome、recordedAt | 主键 id；唯一 [packageId+seq]；observationId |
| photos | id、observationId、blob、mimeType、width、height、byteSize、sha256、addedAt、capturedAt? | 主键 id；唯一 observationId |
| commands | id、fingerprint、receipt、committedAt | 主键 commandId；同一命令只提交一次 |

id 使用 UUID；seq 是同一个包装内递增的整数，每个观察或反馈占用一个 seq。revision 保存该包装最新 seq。不同 store 的 seq 唯一性由同一事务的 revision 递增保证。首版不允许用户修改包装身份或删除历史事件。

source = manual | ai-confirmed | mock-confirmed；outcome = found | not-found。时间使用 UTC ISO 8601 字符串，UI 本地化显示；同设备时钟可能变化，所以业务顺序使用 seq，不按时间戳决定覆盖。

nameKey、labelKey = trim + Unicode NFKC + toLowerCase，用于匹配与唯一性；原始显示名另外保留。首盒可以不填标签，存 label/labelKey=""，界面显示“未命名包装”；已有同名包装时，新增包装必须有非空且不重复的标签，必须显式选择新增。事务内检查同名情况，防止两个标签页同时新增无标签包装。字段预算：药名 1—120 字符，标签 0—40，位置 1—200，原文最多 1000 字符；按 Unicode 码点计数，规范化后重做空值校验。

引用关系：包装一对多观察；观察一对多反馈；观察零或一张照片。仓储在事务中验证关联对象存在且属于同一包装。删除本地演示库属于独立重置操作，不能作为失败恢复或 schema 升级手段。

## 2 读模型与当前状态

对某个包装，取 seq 最大的观察 O；只取关联 O 的反馈，按 seq 得到最新 F。

| 条件 | ClueView 状态 | 显示 |
| --- | --- | --- |
| 没有观察 | empty | 暂无位置线索 |
| O 存在且无 F | recorded | 最近位置，当前是否仍在未确认 |
| F 为 not-found | not-found | 该位置本次未找到，不代表用完 |
| F 为 found | found-at-time | 在 F 的时间确认找到，不保证未来在位 |

“同处找到”新增反馈，不复制位置或照片；“别处找到”新增观察。旧观察的失败反馈不会参与新观察状态推导。历史查询将两类事件合并按 seq 排序，照片来自具体观察，不能按包装获取最后一张照片后随意展示。

ClueView 应包括 package、observation、latestFeedback、state、lastConfirmedAt、photoMetadata；列表不读取图片 Blob，只有详情/放大时按 photoId 读取。

## 3 写命令与事务

命令结构如下，供服务层实现使用，不是 HTTP JSON（PreparedPhoto 包含 Blob）：

```typescript
type PreparedPhoto = {
  blob: Blob; sha256: string; mimeType: 'image/jpeg';
  width: number; height: number; byteSize: number;
  addedAt: string; capturedAt: string | null;
};
type NewPackageRecord = {
  kind: 'create-record'; commandId: string;
  medicineName: string; label: string; locationText: string;
  source: 'manual' | 'ai-confirmed' | 'mock-confirmed';
  photo: PreparedPhoto | null;
};
type ExistingPackageRecord = {
  kind: 'record-location'; commandId: string;
  packageId: string; expectedRevision: number;
  locationText: string;
  source: 'manual' | 'ai-confirmed' | 'mock-confirmed';
  photo: PreparedPhoto | null;
};
type FeedbackCommand = {
  kind: 'feedback'; commandId: string; packageId: string;
  observationId: string; expectedRevision: number;
  outcome: 'found' | 'not-found';
};
type SaveReceipt = {
  commandId: string; packageId: string; observationId: string;
  feedbackId: string | null; revision: number; committedAt: string;
};
```

source 由应用根据草稿解析模式产生，不接受模型直接设置。新记录 ID 与时间由事务提交路径生成，返回后使用回执导航；重试命中回执时不重新生成。

新增包装与首条观察：在 packages、observations、photos、commands 的同一 rw 事务内，校验唯一标签，插入包装（revision=1）、观察（seq=1）、可选照片和命令回执。事务完成才返回保存成功。

已有包装的新观察：命令带 packageId、expectedRevision、位置、可选照片。事务读取包装并核对 revision，再递增，插入新观察与可选照片。没有新照片则 photoId=null，不能继承旧值。

查找反馈：命令带 packageId、observationId、expectedRevision、outcome。事务校验包装版本、观察归属与是否仍为最新观察，再递增 revision 写反馈和命令回执。版本不符返回 STALE_RECORD，保留输入并提示刷新线索后重新确认，不自动把旧页面的反馈附到新位置。

事务里只做数据库操作和同步规则检查。图片解码、压缩、SHA-256 与网络调用提前完成。事务异常必须向外抛出，不能在内部吞错导致部分提交。

## 4 幂等与失败恢复

- 每次用户确认生成 commandId；同一次请求失败后重试使用相同 ID。
- fingerprint 使用固定字段顺序序列化，包含动作、目标、expectedRevision、将实际持久化的去首尾空白显示字段、source 及图片 SHA-256 和元信息（含固定的 addedAt/capturedAt）。比较键与显示值均固定，避免不同显示内容被误判为相同命令。不含服务生成的 ID 和每次重试改变的当前时间。
- 事务内先查 commands：同 ID 同摘要返回原回执；同 ID 不同摘要返回 COMMAND_CONFLICT。
- 命令回执写入与业务写入在同一事务；重复命令检查先于 revision 冲突检查。
- 用户修改字段或移除照片后是新命令，生成新 ID；保存中禁用编辑与重复操作。
- 出现配额不足或写入失败，整笔回滚；保留当前页面草稿，允许重试或明确移除图片再保存。

草稿不承诺跨刷新恢复；已提交但 UI 未收到结果，可以在当前会话用相同 ID 找回回执。重新打开时查询已保存数据，不自动重放未知草稿。

## 5 查询、索引与升级

搜索 trim 后按 nameKey 包含匹配，offset/limit 分页（默认 20，最多 100）；小型家庭数据允许扫描规范化药名，避免为少量数据引入全文索引。先稳定按 nameKey、labelKey、id 排序再切页；不加载 photos Blob。

历史按 packageId 与 seq 查询，使用 beforeSeq 游标（不含该 seq），默认 20、最多 100 条。多标签页写入通过同库事务与 revision 检查防止静默覆盖；UI 可通过 Dexie liveQuery 或重新聚焦读取更新。

schema v1 在初次建库时定义；以后通过递增版本的迁移处理，保留旧数据。升级被其他标签页阻塞时提示关闭旧页；迁移失败提示恢复操作，不清库重建。

读取失败不显示成“无记录”；明确区分 DB_UNAVAILABLE 与正常空结果。图片损坏时显示图片不可用，文字与历史仍可查看。

## 6 保存边界与测试

浏览器的 origin、配置文件、清理操作会影响数据。正常刷新可恢复不等于永久保存；配额或系统清理可能导致损失。可尝试 Storage API 的 persistent storage 请求，但拒绝时仍需正确处理，不宣称保证保留。首版没有云备份与跨设备恢复。[MDN 存储说明](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

测试：同名标签唯一；观察与图片插入失败整体回滚；同命令两次只产生一条；同 ID 改内容冲突；旧 revision 不能写；旧位置 not-found 不污染新观察；时钟倒退仍按 seq 排序；成功反馈不刷新旧照片拍摄时间；跨标签页同时提交；浏览器刷新后读取真实 Blob。

原始自然语言描述仅驻留草稿与解析请求，首版不永久存储；保存经核对的结构化字段即可。
