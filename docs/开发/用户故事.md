# 家庭药箱位置线索 用户故事

版本：0.2 · 日期：2026-10-10 · 状态：开发前草案，所有故事尚未实现、尚未验收；新增用户提出的位置照片能力。

本轮围绕一个任务展开：用户寻找一种已明确的药品时，利用已有位置线索决定先找哪里，并根据寻找结果确认或纠正记录。

依据：[初步产品设计](../初步产品设计.md)、[MVP 决策草案](../MVP%20决策草案.md)、[六屏原型](../prototype/位置线索原型.png)。本文将设计转为可实现、可验收的用户故事；验收条件是预期行为，不是已完成的测试结果。实现分层和契约见[前后端设计与开发方案](前后端设计与开发方案.md)。

## 1 用户与范围

核心用户：无长期固定用药管理需求，药品分散存放在住处与随身物品中，不愿逐次记录存取，需要寻找一种已明确药品的年轻人。

记录时机暂定为整理药箱或放置药品时，是否愿意执行仍待验证。用户不需要为了使用查找功能而记录每次移动或服用。

第一版服务单用户、单设备；管理对象是可区分的实物包装，而不只是药名。位置、时间和来源均来自已有记录或用户确认。无记录不代表没有药，未找到不代表用完，曾经找到不代表现在仍在。

不纳入本轮：诊断、选药、剂量调整、库存数量、过期提醒、自动补货、家庭成员协作、账户、OCR、语音和真实硬件感知。

## 2 故事地图与优先级

主路径：记录 → 核对保存 → 按药名查找 → 查看线索 → 实际寻找 → 反馈或更新。

P0：本轮 Demo 必须交付的核心故事或必要异常；P1：核心闭环稳定后补充。开发顺序与优先级不同：AI 是 P0，但在手工闭环之后接入，以便独立验证其价值。

| 编号 | 用户故事 | 优先级 | 原型映射 | 依赖 |
| --- | --- | --- | --- | --- |
| US-01 | 手工留下位置线索 | P0 | S2 手工入口、S3 | 无 |
| US-02 | 核对并可靠保存 | P0 | S3 → S4 | US-01 |
| US-03 | 区分同名的不同包装 | P0 | S3 补充选择状态 | US-01、US-02 |
| US-04 | 按已知药名查找 | P0 | S1 → S4，补充结果列表/空态 | US-02、US-03 |
| US-05 | 理解位置线索的依据与局限 | P0 | S4 | US-04 |
| US-06 | 确认在原位置找到 | P0 | S4 补充确认状态 | US-05 |
| US-07 | 报告未找到并结束查找 | P0 | S4 → S5 | US-05 |
| US-08 | 找到后更新位置 | P0 | S5 → 位置编辑 → S6 | US-02、US-07 |
| US-09 | 用一句话生成待核对记录 | P0 | S2 → S3 | US-01、US-02、US-03 |
| US-10 | AI 不确定或失败时继续操作 | P0 | S2/S3 补充错误状态 | US-09 |
| US-11 | 查看某盒药的历史线索 | P1 | S5 历史入口、S6 | US-06、US-07、US-08 |
| US-12 | 拍照留下位置线索 | P0 | S2/S3 照片入口、S4 照片预览，待补图 | US-01、US-02、US-05、US-08 |

US-12 是本轮用户新增需求。首版按“文字位置＋可选现场照片”实现：功能纳入 P0，但用户可以跳过拍照，不增加每次移动必须登记的要求。照片的价值是帮助辨认收纳场景，不默认自动识别药品或持续追踪位置。

P1 不意味着可以删除历史数据：原始观察与反馈的保留属于 P0；完整历史浏览界面属于 P1。若 P1 未实现，不展示无响应的历史入口。S6 可先展示与本次更新相关的最近记录。

## 3 用户故事与验收条件

### US-01 手工留下位置线索

作为整理药箱或放置药品的用户，我希望直接填写药名、包装标签和位置，以便以后寻找时有线索可查。

**验收条件**

- 从找药首页可以进入记位置，并选择手工填写，不依赖 AI 可用。
- 药名和位置去除首尾空白后不得为空；缺失时在对应字段提示，并保留其他已填内容。
- 用户可以输入“药箱上层”或“黑色背包前袋”等自由文本，不要求先维护地点目录。
- 包装标签用于区分同名药，例如“随身盒”；同名包装处理按 US-03 执行。
- 提交后进入可核对状态；尚未确认的草稿不出现在查找结果中。

**边界**：输入“包里”可以保留这一模糊程度，不补写用户未提供的具体包或口袋。

### US-02 核对并可靠保存

作为录入位置的用户，我希望保存前核对内容，并明确知道是否保存成功，以免之后依赖错误或丢失的线索。

**验收条件**

- 核对页展示可编辑的药名、包装标签和位置；点击确认前不写入正式位置记录。
- 保存成功后进入该包装的位置线索页，展示用户确认时间和来源。
- 刷新页面或重新打开同一浏览器、同一站点后，已保存记录仍可查询；清除浏览器数据、跨设备同步不在保证范围内。
- 保存失败时明确显示“未保存”，保留当前输入，允许重试，不进入成功状态。
- 连续点击确认、保存中的重复操作不产生重复包装或位置记录；失败后重试同一次提交不重复写入。
- 从核对页返回编辑时保留本次草稿；本轮不要求草稿跨刷新恢复。

### US-03 区分同名的不同包装

作为拥有多盒同名药的用户，我希望明确记录对应哪一盒，以免一盒药的位置覆盖另一盒。

**验收条件**

- 输入已存在的药名时，允许选择已有包装或明确新增一盒，不自动合并。
- 选择已有包装会明确显示其标签，本次保存新增该包装的位置观察，保留旧观察。
- 新增同名包装必须提供与已有同名包装不同的区分标签；重复或空标签提示修改。
- 查询同名药返回可区分的包装项，用户选择后再显示对应位置。
- 更新或反馈只作用于选中的包装；另一盒的位置和反馈保持独立。

**范围**：不实现拍照自动识别包装、药名同义词合并或药品数据库校正。

### US-04 按已知药名查找

作为已经知道要找哪种药的用户，我希望按名称检索已经保存的记录，以便进入相应包装的位置线索。

**验收条件**

- 输入为空或只有空格时提示输入药名，不返回猜测结果。
- 首版采用已记录药名的文本匹配；建议去除首尾空白并支持包含匹配，英文忽略大小写。此检索规则为本故事提出的实现约定，不涉及药理相似性。
- 单个匹配包装可直接进入线索；多个匹配包装先显示药名和区分标签供选择。
- 无匹配时显示“暂无位置线索”，允许修改搜索或在实际找到后记位置，不显示“没有库存”。
- 新用户没有记录时显示空态和记录入口，不把演示数据当成用户真实记录。

### US-05 理解位置线索的依据与局限

作为准备去找药的用户，我希望看到最近记录的位置、时间和来源，以便判断是否值得先去那里找。

**验收条件**

- 位置优先展示，并同时显示所选药名、包装标签、确认时间和来源。
- 没有后续观察时显示“当前是否仍在，尚未确认”，不将历史位置表述为实时定位。
- 来源区分手工确认和 AI 辅助后确认；二者均以用户核对后的事实为记录依据。
- 若最近位置已被反馈为未找到，再次查询仍显示该反馈，不恢复成没有失败记录的推荐。
- 更早的位置可以作为历史查看，但不自动升级为当前有效位置；不生成没有记录的备选地点或准确率。
- 时间按用户当地时间展示，保存值能够正确排序；不因显示时区变化改变先后关系。

### US-06 确认在原位置找到

作为已经在记录位置找到该包装的用户，我希望确认这次结果，以便后续查找时知道线索最近被核实过。

**验收条件**

- 选择“在这里找到了”后，新增对该包装、该位置的找到观察，并展示本次确认时间。
- 原记录和既有失败反馈保留；最近成功观察决定当前展示，不被更早的失败反馈覆盖。
- 文案表达“在某时确认找到”，不承诺包装会一直留在这里，不推断服用或余量。
- 写入失败时不展示已经确认成功，允许重试；重复点击同次确认不重复写入。

### US-07 报告未找到并结束查找

作为按线索寻找却没找到的用户，我希望标记这条线索本次没有帮助，并能结束任务，以免反复被引导到同一地点。

**验收条件**

- 从位置页选择“这里没找到”后，新增关联该位置观察的失败反馈，并显示反馈时间。
- 页面明确显示“本次未找到”“这不代表已经用完”；无其他有效线索时说明暂无更多线索。
- 不修改数量，不删除包装，不凭空推荐其他位置；原始位置记录仍保留。
- 可以选择“暂时结束查找”回到入口，不要求填写新位置或确认药已用完。
- 稍后再次查询仍可见本次未找到状态；该反馈不影响其他包装。
- 反馈保存失败时提示未记录成功并允许重试，不能只改变界面而丢失反馈。

### US-08 找到后更新位置

作为后来在别处找到药的用户，我希望给同一包装补充新位置，以便下次从更新的线索开始找。

**验收条件**

- 从未找到状态进入位置编辑时，携带当前包装身份，明确显示药名和标签。
- 新位置为空时不能保存；用户填入并确认后新增位置观察，而不是新建另一盒药。
- 取消编辑不改变已保存的位置与反馈；返回后仍能看到未找到状态。
- 保存成功后显示新位置及确认时间；再次查询优先显示新观察。
- 原位置和未找到反馈保留，不将旧位置改写成新位置，也不让旧失败反馈使新位置失效。
- 保存失败时保留输入，旧状态继续有效，不显示更新完成。

### US-09 用一句话生成待核对记录

作为不想逐项填写的用户，我希望描述一次放置动作后得到整理好的草稿，以便用较少操作完成记录。

**验收条件**

- 输入“这盒布洛芬放在黑色背包前袋”后，可以生成药名与位置候选，并进入核对步骤。
- 展示或保留原始描述以供核对；未提及的包装标签由用户填写或选择，不凭空生成事实。
- 解析中的状态可见，避免重复提交；解析结果不自动保存，最终仍按 US-02 确认。
- 解析不能自动选择同名包装；发生冲突时按 US-03 让用户选择。
- 界面与运行说明明确标识真实解析或 Mock；Mock 的预设输出不被表述为真实模型效果。
- 查询位置、保存和状态变化使用已有数据与明确规则，不让模型推测未知位置。

**验证假设**：输入、等待、核对、纠错的总时间或操作负担比手工表单更低。功能通过不代表该假设已成立。

### US-10 AI 不确定或失败时继续操作

作为遇到解析问题的用户，我希望保留输入并能手工完成，以免必须反复尝试才能留下记录。

**验收条件**

- 缺少药名或位置时，标明需要补充的字段，允许编辑，不生成默认药品或地点。
- “那盒药”“放回原处”等无法根据已选包装与记录明确解释的描述，要求用户确认，不直接写入。
- 解析超时、服务不可用或返回格式异常时，保留原文并提供重试、手工填写入口。
- 转手工后，已有用户输入和可核对内容仍可查看；缺失字段继续按手工规则校验。
- 切换为手工或开始新的解析后，迟到的旧响应不覆盖当前输入或用户修改。
- 不默默切换到 Mock 并宣称解析成功；医疗问题不生成诊断或选药结果，提示本工具用于位置记录。

### US-11 查看某盒药的历史线索

作为想了解线索为何发生变化的用户，我希望查看该包装的记录与反馈，以便理解最近位置的来由。

**验收条件**

- 按时间展示位置确认、找到、未找到事件，显示对应位置和来源。
- 当前线索与历史区分；历史位置明确不代表仍在，不显示为自动推荐地点。
- 仅展示所选包装的事件，不混入其他同名包装。
- 查看历史不会修改状态；没有历史时显示明确空态。

### US-12 拍照留下位置线索

作为整理或放置药品的用户，我希望拍下药盒所在的收纳位置，并在下次查找时看到这张照片，以便更容易认出具体容器、口袋或抽屉。

**典型情境**：将“随身盒”放进黑色背包前袋时，拍摄能辨认背包与前袋的场景，和文字“黑色背包前袋”一起保存；查找时结合图片判断去哪里翻找。建议拍摄收纳环境，图片不必包含可读取的药品文字。

**验收条件**

- 新增位置或找到后更新位置时，可选择拍照或从本机选图；每条位置观察首版最多附一张照片，也可不附照片完成原流程。
- 可用设备上允许拍照；浏览器不能直接调用相机或用户拒绝权限时，提供选图或继续填写文字的路径，不阻断记录。
- 照片进入草稿后可预览、重拍/替换或移除；用户确认保存前不成为正式位置线索。
- 照片与具体包装的这一次位置观察绑定，不与药名笼统绑定；保存前仍核对包装标签和文字位置。
- 查找页展示该位置观察的照片缩略图，可放大查看；同时显示位置、时间、来源与状态，不能只展示照片而隐藏“尚未确认”。
- 本次直接拍摄可记录拍摄时间；从相册选择时若真实拍摄时间无法可靠确定，显示“拍摄时间未知”，并单独显示添加或确认时间，不把导入时间当作拍摄时间。
- 明确表达照片反映拍摄时的场景，不表示药目前仍在那里；未找到后照片仍保留，但随原观察显示“本次未找到”。
- 新位置保存新照片或不附照片时，不自动沿用旧位置照片。原照片随旧记录保留，不误展示为新位置的现场图。
- 图片和文本在本次记录中一起可靠保存；图片保存失败时不显示完整保存成功，保留当前草稿供重试，或由用户明确移除照片后仅保存文字。
- 刷新后仍能看到已保存照片；文件过大、格式不支持或图片读取失败时给出明确提示，允许换图或改用文字。
- 相册里可能包含私人环境信息。仅保存用户主动选择的图片，不自动读取其他照片；首版不提取 GPS，不上传图片给 AI，位置照片采用本地持久化。

**与 AI 的关系**：位置照片先作为用户可读的辅助证据；US-09 仍处理文字输入。不承诺仅凭图片识别药名、准确抽取收纳位置或找到照片外的物品。自动图像理解留待验证照片本身是否有价值后再决定。

**验证假设**：照片能减少文字位置描述的歧义，而且拍摄、核对和查图成本可以接受。对比“只有文字”和“文字＋照片”的地点辨认任务，记录是否能认对位置及额外操作负担；不能据此证明长期位置准确。

## 4 开发批次与完成标准

| 批次 | 包含故事 | 可演示结果 |
| --- | --- | --- |
| 第一批 手工闭环 | US-01 至 US-05 | 手工记录、核对、刷新后查询，支持无记录与同名包装 |
| 第二批 寻找反馈 | US-06 至 US-08 | 找到、未找到、结束查找、更新位置，历史数据保留 |
| 第三批 位置照片 | US-12 | 拍照或选图、预览核对、持久化、查看，旧照片不混入新位置 |
| 第四批 智能录入 | US-09、US-10 | 自然语言生成草稿，失败后转手工，完成同一保存流程 |
| 第五批 有余量再做 | US-11 | 独立浏览完整历史 |

每个故事完成前：验收条件已实际检查，主流程与相关失败路径可重复演示，写入后的状态经刷新核对；真实能力与 Mock 标识一致。规则性行为应有针对性的测试，视觉小改动不额外堆叠测试。

首次开发还需建立项目与启动脚本、数据持久化适配、AI 解析适配及示例数据。这些是工程任务，不伪装成用户故事。真实模型密钥由服务端保管，具体技术实现另行拆分。

位置照片新增图片持久化与读取职责；不宜直接把大量图片编码塞进文本存储。实现前选定图片存储、格式与大小限制、压缩策略和失败恢复方式，并写入技术方案。图片条目至少区分添加时间、可确认的拍摄时间以及所属位置观察。新增照片能力会增加实现与测试成本，应如实调整投入记录，不能同时删除智能能力与关键异常以维持原时间表。

## 5 端到端验收场景

以下药名、位置和包装标签仅作为演示夹具。

| 场景 | 操作与预期 |
| --- | --- |
| 新用户 | 空白启动，查询布洛芬，显示暂无线索；可以进入记位置 |
| 正常记录 | 手工填写布洛芬、随身盒、黑色背包前袋，核对保存；刷新后查到时间和来源 |
| 关键异常 | 在背包前袋没找到，提交反馈并结束；再次查询仍显示本次未找到，不变成零库存 |
| 找回纠错 | 对同一随身盒补充行李箱内侧袋；查到新位置，旧记录与未找到事件仍保留 |
| 再次确认 | 在新位置找到后确认，展示新的确认时间，不承诺持续在位 |
| 同名两盒 | 新增布洛芬、家用盒、药箱上层；查询时可选两盒，更新随身盒不改变家用盒 |
| AI 降级 | 模拟解析失败，原文保留；转手工并核对后可以保存，模式标识真实 |
| 保存失败 | 模拟写入失败，页面保留输入并提示未保存；恢复后重试，仅出现一条正式记录 |
| 位置照片 | 为随身盒添加背包前袋照片并保存，刷新后可放大查看；相册照片时间未知时不显示为刚拍摄 |
| 照片失效与更新 | 对背包线索反馈未找到，再记录行李箱且不附照片；新位置不能显示旧背包照片，旧照片仍在旧观察中 |
| 相机或图片失败 | 拒绝相机权限、选择不支持的文件或模拟图片保存失败；可以换图或明确移除照片后继续文字记录 |

## 6 开发前与后续需要验证的判断

- 用户是否有愿意记录的自然时机，低频记录能否覆盖实际查找需求。
- 用户是否能区分最近记录、本次未找到和实时库存。
- 同名包装标签是否容易理解，是否引入过多额外输入。
- AI 相比手工表单是否降低总成本，而非只减少打字。
- 位置照片是否比文字更有助于辨认收纳场景，用户是否愿意拍摄，是否误以为照片代表实时位置。
- 原型缺少的包装选择、无匹配、位置编辑和错误状态，应在实现时补全，不视作新增业务范围。

上述研究判断不作为功能通过后的自动结论。试走记录需注明参与者、任务、观察和修改；不得用模拟演示替代真实使用效果。
