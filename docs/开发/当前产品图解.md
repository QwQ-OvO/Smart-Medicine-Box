# 当前产品图解

核对日期：2026-10-10。本组 SVG 按当前源代码绘制，参考提供截图中的“模块总览 → 系统协作 → 场景决策 → 服务泳道”组织方式。截图中的业务控制台、客服、会员和结算不属于本项目功能。

本产品是**家庭药箱位置线索应用**：记录一盒药曾经放在哪里，按药名查找记录，再通过反馈或新位置补充线索。用户确认后的本机记录是事实来源，AI 输出是待核对草稿。

## 1 产品架构设计概览

按记录、查找、反馈历史、支撑能力分组，表达产品能力而非四套独立后台。

![产品架构设计概览](diagrams/01-product-overview.svg)

## 2 系统协作与数据流

当前界面流程集中在 `App.tsx`，本地持久化由 `MedicineStore` 实现，状态由 `deriveClue` 推导。图中描述实际结构，不把早期方案中拟议的独立应用服务、端口层和页面目录画成已经存在。

![系统协作与数据流](diagrams/02-system-data-flow.svg)

## 3 查找场景与处理决策

搜索零条结果显示空态，一条结果直达线索，多条结果选择包装。下半部分列出当前 UI 的状态与动作。未找到状态当前提供“在别处找到了，更新位置”和“暂时结束查找”，没有直接的“又在原处找到了”按钮。

![查找场景与处理决策](diagrams/03-search-decisions.svg)

## 4 记录位置与核对保存泳道

手工填写和一句话整理均需要用户确认，照片可选。已有包装通过 `/record?package=:id` 更新位置，新增观察而不覆盖历史；已有包装的药名和标签保持固定。

## 当前实现与早期方案的区别

- 实际路由为 `/`、`/search`、`/record`、`/clue/:id`、`/history/:id`，不是早期拟议的 `/packages/:id`。
- 页面使用 `useState` 等 hooks，集中在 `App.tsx`；仓储与领域规则已有独立文件。
- 当前照片输入最多 20 MiB，长边缩至最多 1600px，输出 JPEG 最多 2 MiB；未实现早期方案中的 24 MP 解码像素上限。拍摄时间写为 `null`，显示“未知”。
- `deriveClue` 选择 `seq` 最大的位置观察，再取仅关联该观察的最新反馈；无观察为 `empty`。正常创建记录会在同一事务建立首条观察。
- 无账号、跨设备共享、云端药品库、实时库存或硬件联动。Live 适配存在不表示此环境已配置真实模型或验证模型准确率。

本页是代码对应的产品图解，图形检查不替代应用运行验收或用户试用。早期方案中的设计目标仍应与当前实现区分。

## 维护图稿

SVG 使用原生矢量形状与文字，无外部图片、字体请求或脚本，可放大、嵌入文档或导入设计工具。中文字体随设备回退。

```sh
node docs/开发/diagrams/generate.mjs
```
