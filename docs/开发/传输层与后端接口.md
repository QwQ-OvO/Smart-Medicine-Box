# 传输层与后端接口

版本：0.2 自评修订稿 · 2026-10-10 · 状态：尚未实现；修改记录见[设计自评与迭代记录](设计自评与迭代记录.md)。

## 1 传输职责

浏览器本地保存和读取不经过 HTTP。后端只提供文字解析预览、能力模式与健康检查，不接收照片、库存或完整历史。所有接口均走同源 `/api/v1`，开发由 Vite 代理。

HTTP 层负责 JSON、大小限制、超时、请求 ID 与错误映射；ParseService 负责输出语义与模式；provider 负责模型协议。UI 根据稳定 error.code 决定提示，不依赖供应商原始错误文本。

## 2 接口目录

| 方法与路径 | 输入 | 成功响应 | 说明 |
| --- | --- | --- | --- |
| GET /api/v1/health | 无 | 200 `{data:{status:"ok"}}` | 只检查进程；不每次访问付费模型 |
| GET /api/v1/capabilities | 无 | 200 `{data:{parseMode:"mock"或"live"}}` | UI 显示实际模式，不泄露密钥 |
| POST /api/v1/parse-previews | 原始文字和可选已选药名 | 200 解析候选 | 临时计算结果，不建立持久资源，因此不返回 201 |

capabilities 获取失败时将解析标为不可用，手工功能继续；不能将未知模式当作 live。

## 3 解析请求与响应

Content-Type: application/json；请求体上限 16 KiB，text 去除首尾空白后 1—1000 字符，额外字段拒绝。selectedMedicineName 可选、最多 120 字符；不发送本地包装 ID 或位置历史。

```json
{
  "text": "这盒布洛芬放在黑色背包前袋",
  "selectedMedicineName": "布洛芬"
}
```

成功示例：

```json
{
  "data": {
    "mode": "live",
    "status": "ready",
    "candidate": {
      "medicineName": "布洛芬",
      "locationText": "黑色背包前袋"
    },
    "missingFields": [],
    "issues": []
  },
  "requestId": "example-request-id"
}
```

字段缺失依然 200，status=needs-confirmation，候选字段为 null，missingFields 仅允许 medicineName、locationText。诊断/选药等超范围输入返回 status=out-of-scope，candidate 两字段均 null，missingFields=[]。所有 status 都必须经过用户核对，ready 不代表事实已核实。

issues 为必填数组，每项 `{field, code}`：field 允许 medicineName、locationText、text；code 允许 missing-field、ambiguous、conflicting-input、out-of-scope。ready 要求两候选非空且两个数组均为空；needs-confirmation 至少存在一个 issue，缺失字段须与 null 候选及 missingFields 对齐；有值但含糊或冲突时允许 missingFields=[]。out-of-scope 至少包含 `{field:"text",code:"out-of-scope"}`。这样不会把“字段齐全但与已选药名冲突”误当作普通成功。

候选字段长度遵守本地字段预算；额外属性拒绝。服务端验证模型返回，客户端再验证网络响应。模型不返回包装 ID、库存数量、置信分数或任意可执行动作。仅有格式校验不能保证事实正确，页面仍展示原文供核对。

不明确的“原处”“那个包”保留不确定性；若无法整理为位置则返回 null。selectedMedicineName 只是用户已选上下文；原文与其冲突时不得自动改写已有包装身份，要求用户核对。

## 4 错误契约

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请补充有效的描述",
    "details": [{"field": "text", "code": "required"}]
  },
  "requestId": "example-request-id"
}
```

| HTTP | code | 客户端动作 |
| --- | --- | --- |
| 400 | INVALID_JSON | 保留输入，提示请求无法读取 |
| 413 | PAYLOAD_TOO_LARGE | 减少文字，不能重试同样大请求 |
| 415 | UNSUPPORTED_MEDIA_TYPE | 提示只支持 JSON；不接受图片 |
| 422 | VALIDATION_ERROR | 显示字段问题，允许编辑 |
| 429 | RATE_LIMITED | 展示 Retry-After 指定的秒数，允许手工 |
| 502 | PROVIDER_FAILED / INVALID_PROVIDER_RESPONSE | 原文保留，重试或手工 |
| 503 | PARSE_UNAVAILABLE | 解析不可用，手工继续 |
| 504 | PARSE_TIMEOUT | 超时，手动重试或转手工 |
| 500 | INTERNAL_ERROR | 通用错误，附请求 ID，不返回堆栈 |

本地业务错误不伪造 HTTP 状态：VALIDATION_ERROR、DUPLICATE_PACKAGE、STALE_RECORD、COMMAND_CONFLICT、STORAGE_FULL、DB_UNAVAILABLE、PHOTO_INVALID、SAVE_FAILED。前端错误适配将这两类错误统一为可显示对象，但保留错误来源。

## 5 超时、取消和重复请求

provider 总时间预算 12 秒，后端解析 15 秒，前端 18 秒；预算为首版配置值，模型选定后验证。不自动无限重试，不在解析失败后静默切换 Mock。

前端每次解析创建 generation 与 AbortController。用户编辑、转手工、离开页面或发起新解析时取消旧请求；响应只有在 generation 和草稿版本仍一致时才可应用。取消不是保证服务端停止计费，后端也应尽可能传递取消信号。

文字解析无数据库副作用，但重试可能再次产生费用；首版不做复杂跨进程幂等缓存，采用单个在途请求、显式重试与限流。数据库保存命令的幂等见本地持久化设计，两者不得混淆。

## 6 后端实现约束

route 仅处理 schema、状态码和调用 service；Fastify schema 在代码中固定，不接收用户提交的 schema。validation 错误默认状态需统一映射成上表 422；响应 schema 防止供应商额外字段泄露。

provider 接口：`parse(input, signal): Promise<ProviderCandidate>`。Mock 使用明确标识的固定样例与缺字段案例，不能将任意输入硬套成布洛芬和背包。真实实现不赋予模型工具调用权，不执行模型输出；输出结构失效返回 INVALID_PROVIDER_RESPONSE。

日志只记录 requestId、路径、状态码、耗时、模式、错误码；不记录原始描述、图片、密钥或供应商完整请求/响应。HTTP 结果 Cache-Control: no-store。

本地单进程限流可用内存计数（初始每分钟 10 次、同时最多 2 个模型调用）；仅适用于回环演示。公开或多实例部署使用平台限流/共享存储，加访问控制和总用量约束，不能沿用内存计数当作生产防护。provider URL 只由服务端配置，不允许客户端传任意地址。

两个并发槽均占用时立即 429（Retry-After: 2），不建立无限排队。只允许配置的开发/演示 Host 与 Origin；不开放通配 CORS，未知 Origin 拒绝 403 ORIGIN_NOT_ALLOWED。解析仅接受 application/json；本地限制用于缩小访问面，不能替代公开环境的身份验证。后端限流按单进程总量计，不信任客户端伪造的转发 IP。

## 7 契约与测试

contracts 包为 schema 的唯一维护入口；TypeScript 类型由 schema 推导或生成，不手抄两套。请求与结果样例加入契约测试；生成 OpenAPI 文件是实施任务，当前表格与 JSON 样例不是已经运行验证的 OpenAPI。

实现选用固定 JSON Schema、json-schema-to-ts 推导类型，前端用 Ajv 校验响应。schema 不放正则猜药名的逻辑；条件间一致性由 schema 的分支约束与 ParseService 校验共同保证。任何 provider 错误映射到稳定错误码，不能用未捕获异常直接暴露其文本。

至少覆盖 ready、needs-confirmation、out-of-scope、空输入、超长输入、额外字段、错误 Content-Type、上游超时、格式错误、限流、缺配置、Mock 模式标识和迟到响应。Fastify inject 验证 HTTP；浏览器测试验证取消后不覆盖输入。

参考：[Fastify 校验与序列化](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/)。这些状态码、预算和 DTO 为本项目的具体契约。
