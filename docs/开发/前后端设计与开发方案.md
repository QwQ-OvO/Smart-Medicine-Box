# 家庭药箱 前后端设计与开发方案

版本：0.2 自评修订稿 · 2026-10-10 · 状态：设计阶段，尚未创建应用、安装依赖或运行测试。自评结论见[设计自评与迭代记录](设计自评与迭代记录.md)。

本方案承接[用户故事](用户故事.md) US-01 至 US-12，采用本地优先的 Web 应用：浏览器保存包装、位置观察、反馈和照片，轻量后端只负责文字解析。用户核对后的本地记录是事实来源，模型输出只是草稿。

## 1 架构决策与技术选型

| 部分 | 首版选择 | 理由与边界 |
| --- | --- | --- |
| 语言 | TypeScript，strict 模式 | 前后端共用契约类型，减少字段不一致 |
| 前端 | React + Vite | 交互型单页应用，不依赖服务端渲染；沿用前期候选 |
| 样式 | CSS Modules + 现有设计 tokens | 页面少，优先复用原型字号与颜色；不用两套组件库 |
| 路由 | React Router，少量页面路由 | 支持结果详情、浏览器后退；录入过程在同一路由内切换状态 |
| 状态 | React useReducer + 局部 hooks | 草稿是短生命周期状态；不引入 Redux 或全局服务器缓存 |
| 浏览器数据库 | IndexedDB + Dexie | 结构化数据和图片 Blob 在同一数据库事务保存 |
| 图片 | 浏览器解码、Canvas 转码、Blob | 本地处理，首版不上传图片给后端或 AI |
| 后端 | Node.js 24 LTS + Fastify | 提供校验、错误处理和一个文字解析服务；不是通用药品后台 |
| HTTP 契约 | JSON Schema + TypeScript 类型 | Fastify 请求/响应校验，前端校验解析响应；公共包保持无平台依赖 |
| 测试 | Vitest、fake-indexeddb、Playwright | 分别覆盖规则、事务与真实浏览器流程；Fastify inject 测 HTTP |
| 包管理 | npm workspaces + 单一 lockfile | 一个仓库两个应用和一个共享包，不引入额外 monorepo 编排工具 |

版本策略：以上是选型，不是已安装版本。实施时核对 Node、Vite、Fastify 与插件兼容范围，在 package.json 和 lockfile 固定实际组合；不将“latest”作为可复现运行说明。供应商 SDK 仅放在后端 provider 适配中，供应商和模型通过服务器配置指定。

没有选择 localStorage 存照片：图片容量、同步写入和跨记录一致性不适合这个用途。没有引入 PostgreSQL、Redis 或对象存储：当前没有账号、跨设备共享或生产部署需求。后端没有数据库层是明确取舍，数据库层仍存在于浏览器应用中。

如果需求升级为多人或跨设备，另行设计身份、权限、服务器数据库和图片同步；不能仅把 local repository 换成 HTTP，就宣称已经支持协作。

升级时的职责迁移：应用服务与权威校验移到后端，浏览器只保留草稿与可丢弃缓存；服务器仓储持有事务，传输层再增加包装、观察、反馈 REST 接口。服务器数据库候选为 PostgreSQL，照片走独立对象存储，并设计先暂存、确认绑定、失败清理的生命周期，不能声称数据库事务能原子提交远程图片。需新增 ownerId、权限校验、版本冲突与数据迁移校验，再决定是否保留离线同步。本轮不提前创建这些表和接口。

## 2 数据流和模块依赖

```text
React 页面 / 表单 / 照片预览
    → 前端应用服务：记录、反馈、查询、解析草稿
        → 领域规则：包装身份、状态推导、字段约束
        → 本地仓储与事务：Dexie → IndexedDB（含图片）
        → HTTP 适配：fetch → 同源 /api/v1/parse-previews
            → Fastify 控制器与 schema 校验
            → ParseService：超时、结果校验、模式标识
            → Provider 适配：真实文字模型 / 显式 Mock
```

依赖方向：界面可以调用应用服务；应用服务使用领域规则和窄仓储接口；领域模块不能导入 React、Dexie、Fastify 或供应商 SDK。基础设施实现接口，由启动入口装配。不要为每个函数建立类或通用 CRUD 基类。

共享包只包含跨 HTTP 的 schema、DTO 和错误码。浏览器的包装/照片模型不发送到后端，不为“共享”而泄露不需要的数据。

## 4 前端展示层与应用服务

| 模块 | 输入/输出 | 主要职责 |
| --- | --- | --- |
| SearchPage | query → PackageSummary[] | trim、空输入提示、选择同名包装、无结果反馈 |
| RecordPage | Draft → 保存结果 | 手工/AI 输入、图片草稿、核对、保存中与失败 |
| CluePage | packageId → ClueView | 展示位置与来源、找到/未找到、更新入口 |
| PhotoViewer | Blob → 临时 object URL | 预览/放大；关闭或替换时 revokeObjectURL |
| MedicineService | 用户命令 → 已提交记录 | 调用事务接口，保证历史与当前状态一致 |
| DraftParseService | 原文 → 可编辑候选 | 请求代次、取消、响应校验；不能直接保存数据库 |

路由建议：`/` 搜索，`/record` 新记录，`/packages/:id` 线索，`/packages/:id/record` 更新。S1—S6 是状态快照，不机械拆成六条路由。查询参数仅携带药名或包装 ID，不携带图片和原始自然语言描述。

草稿状态：editing → parsing → reviewing → saving → saved；失败回到可编辑状态，保留输入。图片处理使用独立 preparing/ready/error 状态，preparing 时不能提交带图保存。取消/返回不改已保存数据。

本地库是已确认事实的唯一来源；UI 不另存一份长期“当前库存”。事务完成后重新读取 ClueView。页面重新聚焦或检测到其他标签页提交后刷新，不用乐观界面伪装写入成功。

## 5 服务层与仓储边界

本地应用服务方法：

```typescript
createRecord(command: NewPackageRecord): Promise<SaveReceipt>
recordLocation(command: ExistingPackageRecord): Promise<SaveReceipt>
submitFeedback(command: FeedbackCommand): Promise<SaveReceipt>
searchPackages(query: string, offset: number, limit: number): Promise<PackagePage>
getClue(packageId: string): Promise<ClueView>
getHistory(packageId: string, beforeSeq?: number, limit?: number): Promise<EventPage>
```

每个写命令包含 commandId；已有包装写入另带 expectedRevision。仓储提供领域所需的少量方法与一个原子提交入口，不提供页面随意组合多个独立写入的能力。

前端服务负责业务约束与错误语义；仓储负责事务、唯一性和存储异常映射。数据库索引不能替代所有业务校验，IndexedDB 没有关系数据库式外键约束。

后端 ParseService 接收文字，校验长度，选择显式模式，调用 provider 并校验返回格式。它不读取浏览器数据库，不判断真实位置，不根据输入执行工具，也不保存用户药品信息。

## 7 照片处理

首版入口用文件选择器，`accept="image/*"` 和 `capture="environment"` 只是设备提示，不保证区分相机和相册。保留选图、移除、纯文字路径。[MDN capture](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture)

初始资源预算：输入最多 10 MiB、解码像素最多 24 MP，长边缩至不超过 1600px，输出 JPEG 不超过 2 MiB，每条观察一张。以上是本项目工程预算，不是浏览器统一限制；正式上机测试后调整。

首版接受可解码的 JPEG、PNG、WebP，拒绝 SVG、动图和解码失败文件。HEIC 若浏览器未转换或不能解码，提示选择 JPEG/PNG；不承诺所有手机图片格式都支持。不能仅信任文件扩展名或 accept 属性，需实际解码并检查尺寸与输出类型。

图片解码、缩放、方向处理与摘要计算全部在数据库事务之前完成。转码后存 Blob，不存 base64；释放 object URL 和图像解码资源。保存前预览以实际转码结果为准。

不从 EXIF 获取 GPS；不保存原图，转码剥离元信息。普通选图即使提示 capture，也将 capturedAt 设为 null；仅未来在应用内实际控制快门时，才可记录该快门时刻。addedAt 与 confirmedAt 分别记录选择和保存时间。

## 8 启动、配置与运行边界

本地开发：Vite 默认固定端口 5173、strictPort 开启，`/api` 代理到仅监听 127.0.0.1:3001 的 Fastify。固定 origin，避免端口自动变化后误以为本地数据丢失。localhost 与 127.0.0.1 的浏览器存储也不相同。

开发与构建后演示如果使用不同端口，本地库不会自动共享；交付时明确一个固定入口，不将空库解释成数据已迁移。手机访问电脑的 localhost 不可行，真机测试需单独准备受控的局域网/HTTPS 入口，其 origin 数据同样独立；首版不宣称已经完成真机相机兼容测试。

计划提供根命令：`npm ci`、`npm run dev`、`npm run typecheck`、`npm test`、`npm run test:e2e`、`npm run build`、`npm start`。当前尚无这些脚本。生产式本地演示由 Fastify 提供构建后的前端和 API，单 origin；监听地址默认仍为回环地址。

配置：`AI_MODE=mock|live`、`AI_PROVIDER`、`AI_MODEL`、`AI_API_KEY`、`PORT`、`HOST`。缺少真实模式配置时启动报错，不暗中改为 Mock。密钥不进入 VITE_ 前缀变量、前端源码或运行日志。

首版不提供账号；回环本地运行不等于可公开部署。若公开真实付费解析，需先加入口访问控制、部署平台限流和用量预算；仅配置 CORS 不能保护费用。公开演示可先固定 Mock 并明确标识，不启用真实供应商密钥。

已加载应用在后端故障时仍可手工记录和查询；不承诺离线首次打开、离线刷新或 PWA 安装，因为首版没有 Service Worker。

## 9 开发批次与检查点

| 批次 | 工作 | 对应故事 | 退出条件 |
| --- | --- | --- | --- |
| A 基础 | workspace、schema、数据库、错误类型 | 全部基础 | 能启动，类型检查通过，事务失败可模拟 |
| B 手工闭环 | 录入、核对、包装选择、搜索、线索 | US-01—05 | 刷新后可查，重名不覆盖，空态明确 |
| C 反馈 | 未找到、再次找到、更新位置 | US-06—08 | 旧反馈不污染新位置，历史保留 |
| D 图片 | 选图、预览、转码、原子保存、放大 | US-12 | 图片失败不半保存，新位置不带旧照片 |
| E AI | HTTP 契约、Mock、真实 provider、降级 | US-09—10 | 超时可转手工，迟到响应不覆盖编辑 |
| F 验收 | 移动端、异常、运行说明 | 全部 P0 | 端到端可复现，记录实际结果 |

US-11 完整历史浏览在 P0 稳定后实现；历史数据保留从第一版开始。照片使范围超过最初纯文本方案，不能把这份工程设计当作两小时完成承诺。

测试重点：deriveClue 纯函数；同名标签约束；图片与文本事务回滚；重复命令；两个标签页冲突；Mock/live 契约；取消与迟到响应；真实浏览器刷新后的 Blob；320/375/414/768px 布局、键盘与放大。fake-indexeddb 无法证明真实配额和相机行为，需目标设备验证。
