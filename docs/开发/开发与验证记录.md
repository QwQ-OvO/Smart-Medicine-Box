# 开发与验证记录

日期：2026-10-10。工具：Codex、Figma MCP、Vitest、Playwright。采用 backend-patterns、api-design、test-driven-development；实际工时由操作者记录，不推算为题目要求的“两小时”。

## 交付范围

完成“手工/一句话记录 → 可编辑核对 → 本机保存 → 按药名查找 → 同名包装选择 → 位置依据 → 找到/未找到 → 更新位置 → 历史回顾”闭环。可上传或拍摄一张位置照片，压缩为 JPEG，去除原始元数据；不冒充已知拍摄时间，不将旧照片自动带入新位置。

| 用户故事 | 实现和验证 |
| --- | --- |
| US-01 / US-02 | 手工录入、必填校验、核对保存；刷新持久化、事务回滚、失败重试、命令幂等 |
| US-03 / US-04 | 同名包装独立、标签冲突提示、药名搜索、无记录说明 |
| US-05 | 显示位置、时间、来源；明确历史线索不是当前库存 |
| US-06 / US-07 | 找到与未找到事件；结束查找；历史找到不阻止后续未找到 |
| US-08 | 新位置替代当前线索，保留旧事件；修订号阻止并发覆盖 |
| US-09 / US-10 | 演示解析、真实服务适配器、人工核对、缺字段和失败回退；忽略晚到响应 |
| US-11 | 时间倒序历史与历史照片；当前展示上限 100 条 |
| US-12 | 相机/相册输入、浏览器压缩、本机 Blob、预览、更换/移除、刷新保留 |

## 开发与自评迭代

1. 先写领域、存储、HTTP 测试，在空实现上观察到 23 条失败，再完成实现得到 23 条通过。
2. 读取 Figma 页面和关键节点设计上下文，用真实表单、按钮和路由实现设计。背景 `#f5f6f8`、强调蓝 `#0064d9`、Noto Sans SC、20px 卡片圆角、52px 主按钮、底部独立操作区。
3. 接通浏览器闭环后验证刷新、同名包装、解析回退。补事务写入失败和并发写入测试。
4. 自评发现历史“找到”状态缺少下次未找到入口：先复现失败，再修复并回归。
5. 照片刷新测试最初在提交事务完成前刷新：修正测试以等待成功跳转，再验证照片仍可读取。
6. 自评发现演示解析将“这盒药”和备选位置当成确定内容：先建立失败测试，随后改为缺字段待确认。
7. 真实服务适配器使用 HTTPS、禁止重定向、不转发上游错误详情，输出继续走共享契约校验；未配置真实凭据，因此不能声称真实模型评测已完成。

## 与设计方案的落实差异

- 使用当前可用 Node.js 22.21.0，而非强制升级到 24；依赖锁定于 package-lock.json。
- 没有服务端药品 CRUD 或数据库：记录和图片属于 IndexedDB，服务端仅代理文字解析。这样与本机 Demo 的数据边界一致。
- 页面当前集中在 App.tsx，领域、存储、共享契约与服务端已分离。后续页面增多时按 feature 拆分，不预先引入完整状态框架。
- 照片使用真实用户输入，不把 Figma 中的示例照片当成用户记录。相机权限和 HEIC 支持取决于设备；当前接受 JPEG、PNG、WebP。
- 本次属于可运行产品原型，不包含云部署、跨设备同步、真实硬件或库存功能。

## 仍需真人验证

自动化测试证明流程和数据规则可执行，不能证明产品假设成立。下一轮邀请 3–5 人完成：记一盒药、隔天查找、模拟原位置未找到、凭照片更新位置。记录独立完成率、步骤误解、耗时，以及是否把“历史位置”误读为实时状态。

真实模型接入后独立评测至少 20 条输入，覆盖明确位置、缺药名、缺位置、指代、歧义、冲突、医疗请求和提示注入。重点指标为不臆造字段、正确要求核对、失败后能继续任务；本次不虚构这些评测结果。

手机真机相机、Safari / Firefox、操作系统低存储环境尚未实测。未保存的草稿只保留在当前页面会话，刷新会丢失；记录已保存后才保证刷新可恢复。
